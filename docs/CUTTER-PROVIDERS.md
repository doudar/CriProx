# Cutter providers

Skarix separates stable machine IDs and capabilities from manufacturer-specific code. Model labels such as Explore 5 do not include an operating system. Platform restrictions belong to providers.

`electron/cutters/catalog.cjs` is data shared by the renderer, project validators and native service. It records manufacturer, provider, driver, supported transports, sheet formats, direct connection/cutting capability and hardware validation. Existing project IDs remain valid. Unknown IDs fail closed. A selectable model is not a promise of a working direct driver.

`electron/cutters/registry.cjs` allows fixed built-in providers. Each provider supplies its ID, platforms, worker entry point, credential version and job validator. The controller obtains the provider from the selected catalog entry. Workers and SDK factories are never selected from renderer-supplied paths or class names. It enforces one active connection and requires a prepared job to match that connection before dispatch.

The Cricut provider lives in `electron/cutters/providers/cricut.cjs`; runtime loading, descriptors, keys, registration geometry and native plots stay under `electron/cutter/`. Its Bifrost adapter uses the inspected family mapping: Explore 5 / Gandalf / 24, Maker 5 / Dumbledore / 20, Joy 2 / Psyche / 21. Keys are protected and stored separately per model. The existing Explore 5 key filename and schema remain compatible. Refresh and forget affect only the selected model.

Explore 5 retains the prior USB hardware evidence. Maker 5 connection and registered fine-point cutting are experimental, with matching family materials required. Joy 2 connection is experimental; registered cutting is disabled until smaller sheets and mat behavior are implemented. The installed renderer uses a separate legacy controller for older Explore/Maker, Joy, Joy Xtra and Venture models; this work does not implement that protocol. Retired cutters are listed with direct connection unavailable. macOS Explore 5 BLE connection and cutting are supported using the same hash-verified runtime and the installed universal DeviceIO executable. Other models and USB remain unavailable on macOS. Mac hardware testing covers authentication, homing and cutting. Keychain persistence still requires packaged-app testing.

To add Silhouette or another manufacturer, add model definitions and a provider with its own worker and job validator. Keep device discovery, transport, units, tool/material handling, page registration, job construction and cancellation in that provider. Add provider-specific IPC or credential handling if needed; the current protected key exchange is Cricut-specific. Do not route another brand through the Cricut geometry or material format. Add manufacturer-appropriate output preparation before enabling registered printing. Enable capabilities only for implemented operations and record physical test evidence separately from simulated tests.

All providers receive declarative contours and explicit user readiness through the controller. Raw packets, arbitrary paths and SDK objects remain private to the native worker. AI design access does not expose cutter control.
